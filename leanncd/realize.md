## 1. The setup

The project has two layers:

- **Executable** — a compiler that takes a tensor computation and produces numbers.
- **Formal** — a machine-checked categorical description of the same computation, which supports
  proofs rather than just execution.

The formalizability claim is that these two layers describe the same thing. The bridge is `realize`
(`LeanNCD/Bridge/Realize.lean`): it takes the compiler's output and is supposed to return the
corresponding formal object.

Currently `realize` contains a `sorry` — the bridge exists as a type signature and a promise, not a
proof. This doc explains what needs to go in that hole and why it is the project's central remaining
gap.

---

## 2. What the formal object is

The formal object is a **morphism in `Br`**, the strict symmetric monoidal category defined in
`LeanNCD/Base/Br.lean`. `Br` is a colored PROP — freely generated by the primitive broadcast
operations (`BrBase` generators), with wires typed by `ArrayType` (dtype + shape).

The string-diagram reading is the most useful mental model: a morphism `BrMorph dom cod` is a
wiring diagram with input bundle `dom : BrObj = List ArrayType` on the left and output bundle `cod`
on the right. Every morphism is built from:

- **`gen`** — a primitive box (`BrBase`), whose `op : BrOp` field identifies the operation kind (`contract`, `maxreduce`, `scatter`, `relu`, `softmax`, `normalize`, `scan`, `scanAffine`, `scanPre`). A `BrBase (dom cod : BrObj)` also carries `inputWeaves` and `outputWeaves`: for each input (resp. output) tensor, a weave annotates each axis of `degree` as `fixed a` — this tensor is indexed by axis `a` — or `tiled` — the operation broadcasts or contracts along this axis for that tensor. The `targetAxes` of a weave (its `fixed` axes) form the codomain of the corresponding reindexing affine map (`StMat degree targetAxes`), which encodes how degree coordinates project to that tensor's actual index expression;
- **`comp`** (`f ; g`) — sequential composition;
- **`tensor`** (`f ⊗ g`) — parallel juxtaposition;
- **`braid`** — a crossing of adjacent wire-bundles.

Two diagrams related by the standard SMC equations (interchange, braid involution, hexagons, unit/
associativity) are equal. Formally: `Hom` is a free term algebra over those constructors, `Rel` is
the smallest congruence containing the SMC laws, and `BrMorph = Hom / Rel`.

**Copy and discard (needed for whole models).** Those four constructors describe only *linear*
(fan-out-free) diagrams — each wire consumed exactly once. Real models are not linear: a residual
connection `x + f(x)` reads `x` twice, self-attention feeds one `x` into three projections, and dead
intermediates are dropped. Expressing that *as a morphism* needs two more generators on every object
— **copy** `Δ : [A] → [A] ⊗ [A]` and **discard** `ε : [A] → I` — forming a commutative comonoid, which
makes `Br` a **CD (copy–discard) / gs-monoidal category**. The comonoid is deliberately *not* natural
(a general operation need not commute with `Δ`), so `Br` stays resource-sensitive and non-cartesian —
which is what keeps contraction and the Markov-kernel operators (softmax, normalize) semantically
correct. Making copy natural would, by Fox's theorem, collapse `Br` to cartesian and destroy that.
These generators are sanctioned by the design (weight tying is already a comonoid `Δ`; the
nonlinearities are already read as Markov kernels), and are **now present in the Lean `Br`**, per-wire
and sorry-free (§5).

The formal object `realize` must produce is **the string diagram of the entire compiled program** in
`Br` — its boxes the program's operations, its wiring (sequence, juxtapose, cross, copy, discard) the
program's data flow.

## 3. The input: the routed DAG

`realize` does not consume source text. It consumes a **routed DAG** — the compiler's fully lowered,
scheduled output. *Routed* means every input of every node has been resolved to the exact output (or
external input) that supplies it. *Lowered* means each node is a single primitive operation.
*Scheduled* means the nodes are linearized in topological order — every producer precedes its
consumers — so the assembly of §4 can process them front to back with all inputs already available.
The concrete type is `ThreadedComposed` (`LeanNCD/DSL/Target.lean`).

### 3.1 Tensor logic programs

A `TLProgram` (`LeanNCD/DSL/Ast.lean`) is a list of declarations (tensors, predicates, linear maps,
axes) and statements. Statements are Einstein-convention assignments: indices appearing on the right
but not the left are implicitly contracted (summed). The running example is a two-layer linear
network:

```
H[i,k] := W1[k,d] · X[i,d]
Y[i,j] := relu(W2[j,k] · H[i,k])
```

Statement 1 computes an intermediate `H` by contracting over `d` (a standard matrix product).
Statement 2 applies a second linear layer contracting over `k`, then a `relu`, producing the output
`Y`. `X`, `W1`, `W2` are external inputs; `H` is internal. Scatter writes and recurrences (`scan`)
are the other statement forms.

### 3.2 The compilation pipeline

`TLProgram.compile` (`LeanNCD/DSL/Compile.lean`) chains nine phases:

```
assignUIDs → resolveDecls → checkReadRanks → checkDtypes → unifyAxes
           → lowerArith → finalizeScans → splitNonlins → schedule → route
```

Two phases determine the graph's shape:

- **`splitNonlins`** peels each nonlinearity onto its own node. Statement 1 has no nonlinearity and
  stays as one `contract` node. Statement 2 splits into a `contract` node computing
  `T[i,j] = W2[j,k] · H[i,k]` and a `relu` node computing `Y[i,j] = relu(T[i,j])`. Total: three
  nodes.
- **`schedule`** does dead-code elimination (backward-reachability liveness `filter`) and currently
  **preserves source order** — it does *not* yet topologically sort (despite earlier wording here).
  `realize`'s fold relies on a topological order; today that holds only because the example programs
  are written producer-before-consumer. A real sort is added in Phase 2 of the §7 plan.

`route` replaces every named tensor input with a `Wire` pointing to the step that wrote it, or to
the external-input sentinel if no step wrote it, and emits the `ThreadedComposed`.

### 3.3 `ThreadedComposed`

```lean
structure ThreadedComposed where
  steps     : List BrBaseP        -- nodes, one primitive each, in topological order
  routing   : List (List Wire)    -- routing[i] = input wires of steps[i]
  nExternal : Nat                 -- sentinel: step = nExternal marks an external input
```

**Nodes — `BrBaseP`.** The `P` suffix denotes *presentation*: `BrBaseP` is the computable,
serializable counterpart of the mathematical `BrBase`, using `List`s in place of `Fin`-indexed
functions and dropping dependent typing — the form the compiler emits and `realize` consumes. Each
step carries:

- `op : BrOp` — the primitive kind: `contract`, `maxreduce`, `scatter`, `relu`, `softmax`,
  `normalize`, `scan`, `scanAffine`, `scanPre`. `BrOp.toString` is the dispatch string consumed by
  the Python execution layer — the seam between the two project halves.
- `degree` — the node's full index space (free axes ++ contracted axes). For step 0, the `contract`
  computing `H[i,k]`, `degree = [i, k, d]`: free axes `i, k` first, then contracted axis `d`.
- `inputWeaves` / `outputWeaves` — per input (and output), a **weave**: for each degree axis,
  `fixed` if that tensor is indexed by it, `tiled` if broadcast or contracted over it. For step 0:
  `W1[k,d]` is fixed on `k,d` and tiled on `i`; `X[i,d]` is fixed on `i,d` and tiled on `k`;
  output `H[i,k]` is fixed on `i,k` and tiled on `d` (the contracted axis).
- `reindexings` — per input, an affine map (`StMat` over signed coefficients) from degree
  coordinates to the input's actual index expression. This encodes transposes, shifts, strides — the
  internal wiring of a node.

**Wires — `Wire`.** `routing[i]` has one wire per input of `steps[i]`. `Wire` is an inductive sum:
`Wire.internal j slot` names output `slot` of producer node `j`; `Wire.external k` names external
input `k`. (It was a `{step, slot}` struct with a `step = nExternal` sentinel; that aliases a
producer at index `nExternal` with external slot 0 once a model has more steps than inputs, so it was
replaced by the unambiguous sum — see §5.) An unresolved read is a hard compile error. `slot` is
currently always `0` (each node has one output).

### 3.4 Worked example

```
H[i,k] := W1[k,d] · X[i,d]
Y[i,j] := relu(W2[j,k] · H[i,k])
```

After compilation (`splitNonlins` + `schedule` + `route`):

```
nExternal = 3         externals: W1 → slot 0,  X → slot 1,  W2 → slot 2

steps[0] = contract   degree [i,k,d]   reads W1, X     →  produces H
steps[1] = contract   degree [i,j,k]   reads W2, H     →  produces T
steps[2] = relu       degree [i,j]     reads T         →  produces Y  (sink)

routing[0] = [ Wire.external 0, Wire.external 1 ]    -- W1, X
routing[1] = [ Wire.external 2, Wire.internal 0 0 ] -- W2; H from output slot 0 of step 0
routing[2] = [ Wire.internal 1 0 ]                  -- T from output slot 0 of step 1
```

External inputs `W1`, `X` feed step 0 (`contract`), producing intermediate `H`. Step 1 (`contract`)
consumes `W2` (external) and `H` (from step 0), producing a pre-activation `T`. Step 2 (`relu`)
applies the nonlinearity and produces the output `Y`.

### 3.5 Correspondence table

| Tensor logic program | Routed DAG (`ThreadedComposed`) |
|---|---|
| one primitive after `splitNonlins` | one node (`BrBaseP`) |
| output + contracted axes | `degree` |
| how a tensor sits in those axes | `inputWeaves` / `outputWeaves` |
| affine index expression (`W1[k+1,d]`, transpose, stride) | `reindexing` (`StMat`) |
| read of a tensor produced by another statement | `Wire.internal` to that producer node |
| read of a declared input tensor | `Wire.external` slot |
| data-flow dependency | DAG edge (`routing`) |
| program result | sink's output |

## 4. The problem `realize` must solve

`realize` must fold the routed DAG into a single `BrMorph dom cod`, using `comp` to sequence nodes,
`tensor` for parallel placement, `braid` to route wires, and — for whole models — `Δ`/`ε` to copy a
value to several consumers and discard dead ones.

Every CD-category morphism factors into layers of the form *(wiring)* ; *(one generator ⊗ identities)*,
where a **wiring morphism** is built from identities, braids, copies, and discards — the comonoid
plumbing that permutes, duplicates, and drops the live wires. `realize` only needs to *construct* one
such factorization, not a canonical one.

The algorithm is a fold over the topologically ordered steps, threading a live pool of wires (the
analogue of Python's operational live pool — but emitted as an explicit morphism, since `Br` has no
free copy):

```
pool ← dom                                  -- ordered bundle of live wires (the external inputs)
acc  ← id dom
for each step sᵢ:
  w   ← wiring morphism that, from `pool`, copies (Δ) each wire sᵢ reads — keeping a copy live if
        later steps read it too — discards (ε) any now-dead wire, and permutes sᵢ's inputs to the front
  acc ← acc ; w ; (sᵢ ⊗ id rest)
  pool ← sᵢ.outputs ++ rest
acc ; (final wiring into cod order)
```

Linear programs are the special case where every `Δ`/`ε` is trivial and the wiring is a pure
permutation — so a permutation-only `realize` is a viable first milestone that the copy/discard
machinery later subsumes.

| `realize` (under `WellFormed`) | `propext, Classical.choice, Quot.sound` | **sorry-free — body closed** |

**The category.** The full `Br : ColoredPROP` instance — `tensorHom`, `swap`, interchange, both
hexagons — is sorry-free. (Source comments calling these "Milestone-B+ sorries" were stale and have
been corrected.) So the SMC building blocks — sequence, juxtapose, braid — exist and are sound.

**The `Wire` encoding.** `Wire` is the unambiguous inductive `Wire.external k | Wire.internal step
slot` (§3.3). It replaced a `{step, slot}` struct whose `step = nExternal` sentinel aliased a producer
at index `nExternal` with external slot 0 once a model had more steps than inputs — fatal for deep
models, and a prerequisite for any correct routing walk.

**The `dom` boundary.** `realize`'s domain is now `realizeDom tc`: the faithful per-external-slot
bundle, each slot's `ArrayType` taken from its first `Wire.external` consuming port — the Lean image
of the Python reference `ThreadedComposed.dom()` (the agreement oracle). `cod` (the last step's
codomain) already matched that reference and is unchanged. A multiply-read external (e.g. a tied
weight) must yield ONE canonical type per slot; rather than import Python's positional unification —
which fuses the reads' axis *identities* (`Context`/`EqualityClass` merge UIDs) and over-strongly
conflates independent index ranges — we rely on Lean's name-based `unifyAxes` for same-named reads
plus a decidable `wellFormedDom` guard requiring all consuming ports of a slot to agree on **rank**
(the count of `fixed` axes — the presentation-level content of shape-agreement, since symbolic sizes
are name-bound; bound-name differences allowed, genuine conflicts rejected). This keeps the
single-occurrence `dom` that weight-tying-as-`Δ` wants, without the identity merge.

**The copy/discard comonoid.** `Br` now carries the per-wire CD generators `copyW : [A] → [A,A]` and
`delW : [A] → []` (new `Hom` constructors), with the comonoid laws — coassociativity, both counits,
cocommutativity — added as `Rel` constructors and exposed as sorry-free `BrMorph` lemmas. They are
deliberately **non-natural** (no `f ; Δ = Δ ; (f⊗f)`), so `Br` gains fan-out without collapsing to
cartesian (Fox). Per-wire was the decisive choice: on singleton lists `++` computes, so coassoc, the
left counit, and cocommutativity are cast-free; only the right counit crosses `[A]++[] = [A]`, handled
by one `HEq` bridge mirroring `tensor_unitr_heq`. The `Br : ColoredPROP` instance stays
`[propext, Quot.sound]` — enlarging `Rel` never invalidates the existing `Quot.sound` proofs. (The
linear NbE model in the off-critical-path `BrNF.lean` cannot interpret copy/discard — one-in-two-out
is not a bijection — so `eval` carries two tracked, deferred `sorry`s there; the realize-side laws are
unaffected.)

**The wiring morphism.** `BrMorph.wiring s sel : BrMorph s (sel.map s.get)` (`LeanNCD/Base/BrWiring.lean`)
realizes any type-preserving selection of a bundle's wires — repeated index ⇒ copy, absent index ⇒
discard, order ⇒ layout — from `copyW`/`delW`/`braid`/`id` alone. All the `cast`/`HEq` work is confined
to the gather primitive `rotateToFront` (one `braid` retyped across `take`/`drop`/`eraseIdx`) and its
inverse; the recursion above them (`pick` = gather-copy-restore, then a fold over `sel`) is
definitional. This is the reusable plumbing the fold calls at each step.

**The assembly fold — `realize`'s body is now sorry-free.** Two layers (`LeanNCD/Bridge/Realize.lean`):
a combinatorial *plan* (`readByLater`, `wirePlan` — pure `Nat`/`Wire`/`List`, `#guard`-tested) and the
typed `interp`. The fold uses a **monotonic pool** (externals, then every step's output prepended — a
produced wire is never dropped, so `reads ⊆ pool` stays easy): `stepPiece` gathers a step's reads with
`wiringBy` (copying via the comonoid where a wire is reused), applies the step beside the carried
wires, and lands on the next pool's types; `interpUpto` composes the per-step pieces; `finalPiece`
selects the output into `cod`. `realize tc h` is `interpUpto ; finalPiece`, verified
`[propext, Classical.choice, Quot.sound]` — **no `sorryAx`**. Because the pool retains every wire and
`wiringBy` copies on demand, this is the *general* construction (whole models with fan-out), not just
the linear case.

**Sound, but conditional — and why that distinction matters.** `realize` now takes a hypothesis
`h : tc.WellFormed` (the type-consistency precondition: the dom guard, per-step producer⊳consumer
type match, single output, and reads-live/topological order). Being sorry-free means the construction
is *sound* — given a well-formed `tc`, the morphism provably exists. But sound is not the same as
*applicable*. Like

```lean
def safeDiv (a b : ℤ) (h : b ≠ 0) : ℤ
```

`realize` cannot be invoked until you *hand it* a proof of its precondition — and for an arbitrary
`tc` you genuinely cannot supply one (an ill-typed graph has no morphism, and there is no junk
`BrMorph dom cod` to fall back on: `Br` cannot conjure a wire from nothing). So as it stands,
`realize` is a sound bridge that **nothing can yet cross**: it cannot be applied to a single real
program without a hand-written well-formedness proof. Discharging that precondition — proving
`WellFormed` holds for every compiled `tc` — is what actually drives programs across the bridge, and
is the first remaining task (§6a).

## 6. The impediments

The construction is done: `Br` with its comonoid, the boundary spec, the wiring morphism, and the
assembly fold are all in place and sorry-free (§5), so `realize tc h : BrMorph (realizeDom tc) codObj`
exists for every well-formed `tc`. What remains is **correctness**, not existence:

**(a) Correctness + well-formedness — the remaining gap.** Two linked obligations, both in
`LeanNCD/Bridge/Agreement.lean` (still `sorry`):

- **`WellFormed` for compiled `tc`** — the theorem
  `(compile p).run s = .ok tc s' → tc.WellFormed` (the honest `∀ p` form; `compile` is in the
  `EStateM CompileError Nat` monad). This discharges `realize`'s precondition on real input and is a
  compiler-correctness result (the `assignUIDs → … → schedule → route` pipeline emits
  topologically-ordered, type-consistent, single-output graphs).

  **CRITICAL FINDING (2026-06-25): `WellFormed` is currently FALSE for compiled programs** — verified
  empirically on the 2-layer net `H[i,k] := W1[k,d]·X[i,d]; Y[i,j] := relu(W2[j,k]·H[i,k])`. Two of
  the four conjuncts fail, so this is a **fix-the-compiler-then-prove** task, not a pure proof:
  - **Conjunct 2 (producer⊳consumer type match) — the killer.** `route`
    (`LeanNCD/DSL/Pipeline/Lowering.lean`) sets every input weave to the step's *own* output weave
    (`inputWeaves := readFactors.map (fun _ => mkWeave)`), so a producer's output type ≠ a consumer's
    input type. On the example, the `H` wire carries type `[i,k]` but the consumer's input weave
    claims `[i,j]`. The degenerate weave also mis-types `reindexings`. **Fix:** `route` derives every
    tensor's wire type *once* into a `nameToType` map and builds both the producer's output weave and
    each consumer's input weave from it (in **producer order**) — making conjunct 2 hold *by
    construction*.
  - **Conjunct 4 (topological order).** `schedule` does not sort (see §3.2); holds only for
    producer-before-consumer source. **Fix:** add a real topological sort to `schedule`.
  - Conjuncts 1 (`wellFormedDom`) and 3 (single output) already hold.

  **De-risk (2026-06-25) — the fix is validated.** A throwaway spike hand-built the *faithful* 2-layer
  `tc` (per-tensor weaves in producer order) and proved `WellFormed` **sorry-free**
  (`[propext, Classical.choice, Quot.sound]`). Conjunct 2 closed by **`rfl`** per index: `weaveToArrayType`
  drops `.tiled` slots, so producer `[fixed i, fixed k, tiled]` and consumer `[fixed i, fixed k]` are
  *definitionally* equal `ArrayType`s. A second spike confirmed the **transpose canary**: with the
  consumer reading `H` transposed, producer-order weaves keep conjunct 2 `rfl`, while read-order weaves
  make it provably false — so the producer-order choice is both necessary and sufficient (the transpose
  lives only in `reindexings`, which `WellFormed` never inspects).

  Note this is well-*typedness*, not behaviour — it makes the morphism *exist* for every program, not
  *agree* with execution; that is the next bullet.
- **Agreement.** A sorry-free `realize` proves the formal morphism *exists*; it does not prove it
  *behaves like the running program*. That is `realize_fromThreadedComposed_agree` and the
  reverse-direction extractor `fromThreadedComposed`. This is what earns "the math describes the
  program."

## 7. Path to close it — the `∀ p WellFormed` plan of attack

The forward construction is landed (§5). The active work is **fixing the compiler so `WellFormed`
holds, then proving the `∀ p` theorem**. Full task-by-task plan with code and tests:
**`docs/superpowers/plans/2026-06-25-wellformed-forall-p.md`** (de-risk results recorded there too).
This is a **resumable checkpoint** — pick up at whichever phase is unstarted.

**Target theorem** (`LeanNCD/Bridge/Agreement.lean`):
```lean
theorem compile_wellFormed (p : TLProgram) (s : Nat) (tc : ThreadedComposed) (s' : Nat)
    (h : (TLProgram.compile p).run s = EStateM.Result.ok tc s') : tc.WellFormed
```

**Progress (2026-06-26):** Phases 0–3 DONE, Phase 4 PARTIAL (branch `wellformed-forall-p`, HEAD
`beb414f`). Task 3.2 (conjunct-2 engine) landed: `tensorAxes` dedups by uid; `buildStep` derives an
internal read's weave from `stmts[nameToStep[rf.1]]` (dropping `nameToType`); `buildStep_output_fixedAxes`
proves a step publishes exactly `tensorAxes` of its rep stmt. Phase 4: `compile_wellFormed` is assembled
in `Agreement.lean` with `compile_eq_route` (EStateM plumbing), `wf_singleOutput` (conjunct 3), and the
`weaveToArrayType_congr` bridge proven sorry-free. **Resume at the three remaining conjuncts**
